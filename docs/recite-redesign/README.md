# 开始背单词模块重设计

## 文档目的

这里保存“开始背单词”模块的设计方案。当前阶段只做产品交互、状态流转和与现有复习计划的融合设计，不直接修改实现代码。

## 配置端与学习端

开始背单词分成两个完全分开的使用端，类似家长负责配置、学生负责学习：

- **配置端**：位于英语学习页或任务配置页，负责周任务、学习次数、每次单词数和单词选择。配置完成后生成可学习任务。
- **学习端**：路由为 `#/recite`，只负责展示和完成当前任务。进入后直接开始学习，不显示配置入口，不提供返回按钮，也不提供退出按钮。

`#/recite` 不承担任务创建、修改或补选单词的职责。没有可学习任务时，也只显示学习端的空状态，不跳转到配置端；配置动作必须由配置端完成。

每个模块先形成草案，由用户逐项确认；确认后将文档状态改为“已确认”，再进入下一个模块。所有模块确认后，才能整理实现拆分和开发顺序。

## 设计原则

1. 学习列表是单词来源，现有 StudyPlan 是复习状态和排期的来源。
2. 背词模块不创建第二套 `stage`、`nextDueAt` 或复习算法。
3. 每个模块只解决自己的问题，跨模块依赖写清楚但不提前替代其他模块的设计。
4. 设计文档使用中文，确认后的结论才可以作为实现依据。

## 当前代码基线

- `src/pages/RecitePage.tsx` 已存在全屏背词页，但当前组件接收外部词数组，选词策略仍未设计。
- `src/hooks/useStudyPlan.ts` 已支持 `done`、`again`、`stop`、`tally`，并区分 `spelling`、`reading`、`meaning` 三类熟悉度计数。
- 现有复习计划中的到期状态、复习阶段和排期字段由服务端派生，背词模块不应自行保存另一份排期。

## 文档状态约定

- `待设计`：尚未进入讨论。
- `待确认`：已有完整草案，等待用户确认或修改。
- `已确认`：方案可以作为后续模块的依赖。
- `已实现`：代码已经按照文档完成，并且文档已同步最终行为。
