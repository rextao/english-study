# 项目文档维护规则

本目录保存**低频读取、按领域拆分**的项目知识。它不是聊天记录，也不是源码的副本；文档只记录能帮助下一次任务快速定位和做出正确改动的稳定事实。

## 文档分层

| 文件 | 作用 | 更新频率 |
| --- | --- | --- |
| `../AGENTS.md` | 全局硬约束、项目地图、最常用的改动落点 | 架构或全局约束变化时 |
| `../README.md` | 面向人的安装、使用、部署说明 | 用户流程或命令变化时 |
| `architecture.md` | 系统边界、数据流和状态归属 | 架构变化时 |
| `frontend.md` | 页面、路由、hook、UI 约定 | 前端结构变化时 |
| `backend.md` | Worker、API、D1 和外部服务约定 | 后端结构变化时 |
| `decisions/` | 不容易从代码直接看出的设计决策 | 做出或推翻重要决策时 |
| `handoff.md` | 当前未完成工作的短交接 | 跨 session 工作时 |

## 动态更新机制

文档采用“稳定事实入库，临时事实出库”的规则：

1. 新增或修改功能后，只更新受影响的文档层，不全量重写文档。
2. 先修改代码，再依据最终实现更新文档；不要把计划当成事实写进去。
3. 只写可验证的信息：文件路径、公开接口、命令、约束和当前行为。
4. 不把 token、密钥、真实数据、完整 transcript 或机器绝对路径写入文档。
5. 如果信息只对当前任务有用，写入 `handoff.md`；任务结束后删除已完成事项或归档到决策记录。
6. 如果代码和文档冲突，以代码和测试为准，并在同一次改动中修正文档。

## 新 session 的最小读取路径

不要默认扫描整个仓库。按任务选择：

```text
所有任务       AGENTS.md
新增/修改页面  + frontend.md + App.tsx + 路由/导航 + 一个相似页面
修改 API/D1    + backend.md + 对应 route/store + 相关测试
改架构         + architecture.md + 相关 decision
继续未完成工作 + handoff.md
```

读取地图后仍需检索实际调用方。文档用于缩小范围，不替代对受影响代码的验证。

## 完成任务时的检查清单

- 是否改变了页面、路由、hook、API、表结构或全局约束？
- 如果改变了，是否更新了对应的领域文档？
- 是否删除了已经不存在的路径、命令或行为？
- 是否把临时状态误写进了长期文档？
- 是否运行 `npm run docs:check`？

`npm run docs:check` 只做轻量结构检查：确认文档引用的关键路径存在、禁止把本机绝对路径写入项目文档，并检查文档目录的入口文件。它不会假装能验证所有行为；行为仍由构建和测试负责。

开发命令 `npm run dev` 会先检查当前 Node 的主版本是否符合 `.nvmrc`。版本不符合时会直接退出，不启动 Vite 或 Wrangler，避免出现页面能打开但 `/api` 代理连接不上 Worker 的假启动状态。
