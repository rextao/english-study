# 文档维护规则

这个目录只放**代码里看不出来、又会影响后续改动**的内容。项目结构、接口、约束、坑都在 `AGENTS.md`，使用说明在根目录 `README.md`，这里不再复制。

## 放什么

| 内容 | 放哪 |
| --- | --- |
| 项目地图、硬约束、接口表、已知坑 | `AGENTS.md`（唯一事实来源） |
| 面向人的安装 / 使用 / 部署 | 根目录 `README.md` |
| 推翻成本高、从代码读不出来的设计取舍 | 本目录 `NNN-<slug>.md` |
| 跨 session 未完成的工作 | 本目录 `handoff.md`，完成即删 |

单份设计稿（某个模块的完整交互方案、验收清单、实施顺序）不进这个目录：方案确认后要么落进 `AGENTS.md` 的稳定事实，要么随实现一起消失在代码和测试里。

## 怎么写

1. 先改代码，再按最终实现写文档；不要把计划写成事实。
2. 只写可验证的信息：路径、接口、命令、约束、当前行为。
3. 不写 token、密钥、真实数据、完整对话或本机绝对路径。
4. 代码与文档冲突时以代码和测试为准，并在同一次改动里修掉文档。
5. 只对当前任务有用的信息写 `handoff.md`，任务结束删条目，不要留成长期文档。

决策记录建议结构：`# 标题` → `## 状态`（accepted / superseded / deprecated）→ `## 背景` → `## 决定` → `## 影响` → `## 相关代码`。新决策推翻旧决策时保留旧文件并标 `superseded`。

## 新 session 怎么读

```text
所有任务        AGENTS.md（读完即可动手）
改架构 / 取舍    + 本目录对应的 NNN-*.md
接手未完成工作    + handoff.md（存在才读）
```

文档只用来缩小检索范围，不替代对受影响代码和测试的确认。

## 检查

`npm run docs:check` 会确认本目录入口存在、`AGENTS.md` / `README.md` 存在，并禁止把本机绝对路径写进项目文档。它只是结构检查，行为仍由 `npm run build` 和 `npm run test:server` 负责。
