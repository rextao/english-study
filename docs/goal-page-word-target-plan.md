# 目标页单词目标方案

> 状态：已实现。
>
> 本文用于下一次实现时对照，避免改动目标页中已经稳定的时间轴和顶部进度功能。

## 一、最终页面结构

目标页从上到下分为三个主要模块：

1. 顶部整体周期进度与下一节点进度
2. 长期目标时间轴
3. 目标详细说明（本次重点重新设计）

目标详细说明中先实现“单词目标”，听、说、读、写要求保留后续扩展空间。

## 二、本次改动边界

### 第一模块：顶部进度区

第一模块只允许做必要的文案调整，不重做样式、不改变布局、不改变进度计算逻辑。

现有整体周期进度和下一节点进度属于已经完成的功能，必须保留：

- 两个进度条的现有布局和视觉样式
- 整体周期进度的计算方式
- 下一节点进度的计算方式
- 百分比和“还剩 X 天”的展示方式
- 移动端响应式布局

### 第二模块：长期目标时间轴

第二模块只允许做必要的文案或目标日期调整，不重做样式、不改变交互、不改变定位逻辑。

必须保留：

- 时间轴、阶段色带、年级行和周期节点
- 今天红点、日期和虚线
- KET 考试图标在轴线末端的定位
- 周期点击区域覆盖日期之间的轴线区域
- 移动端无横向滚动条的适配
- 周期标签上下交错排列的方式

除非后续明确提出视觉问题，否则不要修改第一、第二模块的 CSS 结构或交互实现。

### 第三模块：目标详细说明

第三模块是本次主要重新设计范围：

- 单词目标与周期时间轴建立关系
- 展示当前时间周期对应的目标情况
- 点击其他周期后，切换常驻详情面板
- 四项指标全部使用进度条展示

## 三、单词目标统计口径

### 1. 词汇总进度

词汇总进度按三个能力标签中任意一个有次数的去重单词计算：

```text
wordCount = count(distinct word where
  spellingCount > 0
  OR readingCount > 0
  OR rememberedCount > 0
)
```

同一个单词即使同时有会拼、会读、知意次数，也只在词汇总进度中计算一次。

### 2. 能力标签进度

三个标签独立计算：

```text
会拼 = count(distinct word where spellingCount > 0)
会读 = count(distinct word where readingCount > 0)
知意 = count(distinct word where rememberedCount > 0)
```

不要把三个标签合并成一个分数。三项进度分别用于看出拼写、读音和词义理解的短板。

## 四、周期累计目标

周期目标是累计目标，进入下一周期后不清零：

| 周期 | 累计词数 | 描述 |
| --- | ---: | --- |
| 周期 1 | 670 | Movers 前段核心词 + 第一阶段 Starters 的 350 词 |
| 周期 2 | 830 | 掌握 Movers 后半 160 词 |
| 周期 3 | 1260 | 掌握 Flyers 前半 180 词 |
| 周期 4 | 1460 | +200 KET 核心词 |
| 周期 5 | 2000 | +160 KET 进阶核心词 |

## 五、详情面板行为

### 1. 默认显示当前周期

详情面板不是点击展开，也不存在折叠状态。

页面加载后，根据今天的日期自动选中当前周期，详情面板常驻显示该周期：

```text
周期 1 · 当前周期
目标：670 词
```

### 2. 点击其他周期后切换

点击时间轴中的其他周期后，只切换详情面板内容，不改变时间轴上的今天标记和当前周期标记。

需要区分：

- 当前周期：由日期计算得出
- 查看周期：由用户点击决定

如果用户点击周期 3，详情面板显示周期 3 的数据，但时间轴仍标记真实的当前周期。

### 3. 未来周期

未来周期可以点击查看，数据仍按当前累计标签数据计算：

```text
词汇总进度：128 / 1,260 · 10%
会拼：110 / 1,260 · 9%
会读：96 / 1,260 · 8%
知意：122 / 1,260 · 10%
```

## 六、四项指标全部使用进度条

详情面板中以下四项都必须是独立进度条，不只显示数字：

```text
词汇总进度：128 / 1,260 · 10%
会拼：110 / 1,260 · 9%
会读：96 / 1,260 · 8%
知意：122 / 1,260 · 10%
```

建议结构：

```text
词汇总进度  128 / 1,260 · 10%
████░░░░░░░░░░░░░░░░

会拼        110 / 1,260 · 9%
███░░░░░░░░░░░░░░░░░

会读         96 / 1,260 · 8%
██░░░░░░░░░░░░░░░░░░

知意        122 / 1,260 · 10%
████░░░░░░░░░░░░░░░░
```

进度条百分比计算：

```text
progress = min(100, actualCount / cycleTarget * 100)
```

当实际数量超过目标时，进度条封顶 100%，数字仍显示实际比例，并额外显示超额数量。

例如：

```text
720 / 670 · 107%
████████████████████ 100%
超额完成 +50 词
```

## 七、周期未完成和超额规则

### 当前周期进入下一周期但未完成

不清零，不覆盖，不把上一周期的数据转移掉。

例如周期 1 未完成而进入周期 2：

```text
周期 1 · 未完成
128 / 670
还差 542 词

周期 2 · 当前周期
128 / 830
```

### 周期超过 100%

进度条保持 100% 封顶，实际数字和超额数量继续显示：

```text
周期 1 · 已达成
720 / 670 · 107%
超额完成 +50 词
```

后续周期仍按自己的累计目标计算：

```text
周期 2：720 / 830 · 87%
```

## 八、时间轴与单词目标的关系

每个周期节点同时关联：

- 周期日期
- 周期名称
- 累计词汇目标
- 当前完成情况
- 四项进度条
- 周期描述

视觉层级建议：

```text
轴线上方：阶段色带
轴线中间：今天、周期日期、KET 考试节点
轴线下方：当前查看周期的单词目标详情
```

时间轴负责表达“时间关系”，常驻详情面板负责表达“目标与完成关系”。不要把大量四项进度条直接塞入每一个时间轴节点，避免移动端拥挤；点击节点后更新统一的详情面板。

## 九、实现时的保护要求

实现第三模块时：

- 优先新增独立组件或独立样式类。
- 不要重写第一模块和第二模块的现有 CSS。
- 不要改变时间轴已有的日期计算、节点定位和点击区域逻辑。
- 不要把四项进度条复制到每个时间轴节点中。
- 不要把会拼、会读、知意相加后作为词汇总进度。
- 不要使用“已进行 X 天”，统一使用“还剩 X 天”。
- 移动端必须保持无横向滚动条。

## 十、验收标准

- 页面加载时，详情面板显示当前日期所在周期。
- 点击其他周期后，详情面板切换为被点击周期。
- 当前周期标记和查看周期状态可以同时存在。
- 词汇总进度按三个标签任意有次数的去重单词统计。
- 词汇总进度、会拼、会读、知意四项均有进度条。
- 周期目标使用累计目标 670、830、1260、1460、1800。
- 周期未完成和超额完成状态均能正确表达。
- 第一、第二模块已有布局、样式、计算和移动端行为没有被破坏。
- 运行 `npm run build` 和 `npm run docs:check`。
